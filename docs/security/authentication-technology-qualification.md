# Authentication technology qualification

2026-11-27. The owner selected native Spring Security server-side sessions. The previous browser JWT/DPoP/public-client refresh/popup feasibility study is superseded. Its missing protocol capabilities are no longer implementation gates for the selected architecture.

Spring Boot remains 4.2.0, Java 21. Cached Spring Security 7.2.0 public APIs were inspected using javap for DaoAuthenticationProvider, UsernamePasswordAuthenticationFilter, HttpSessionSecurityContextRepository, ChangeSessionIdAuthenticationStrategy, CsrfAuthenticationStrategy and servlet PathPatternRequestMatcher. No compilation or Maven execution was performed. Spring Session 4.2.0 is managed by the existing Boot BOM; its data-redis artifact was not locally cached during inspection and remains for the owner to resolve. Bouncy Castle bcprov-jdk18on 1.86 is explicitly pinned from the local cache for native Argon2id support; owner dependency/security verification remains required.

The implementation uses the public framework provider, context repository, fixation and synchronizer CSRF components. Company/current-authority checks wrap the native password provider; no custom password cryptography, session credential scheme, token issuer or OAuth server is added. Spring Session Redis uses a secure DefaultCookieSerializer, a separate authentication key namespace and immediate writes. Its session serializer's native Java format is trusted server-only data; Redis write access must therefore be restricted as authentication authority.

Official public contracts consulted: [Spring Security session management](https://docs.spring.io/spring-security/reference/servlet/authentication/session-management.html), [authentication filter API](https://docs.spring.io/spring-security/reference/api/java/org/springframework/security/web/authentication/AbstractAuthenticationProcessingFilter.html), [Spring Session Redis configuration](https://docs.spring.io/spring-session/reference/configuration/redis.html), [cookie customization](https://docs.spring.io/spring-session/reference/configuration/common.html). Local API inspection is stronger version evidence for cached Security classes; linked documentation is not evidence that the new dependency compiles or works in this repository.

Before native WebAuthn implementation, ADR-0004 fixes company-specific exact RP IDs/origins and separate admin RP. Native WebAuthn persistence, ceremony challenge consumption, hardware assurance/metadata, TOTP policy, recovery and browser compatibility remain future qualified work. They are deliberately not enabled in the password-session foundation. Required MFA fails closed.

The owner must run the consolidated [verification procedure](phase04-authentication-foundation.md). Production blockers include MFA/recovery/RBAC/step-up/dual approval, email/invitation lifecycle, audit/notifications, trusted edge source attribution, Redis TLS/ACL/key protection, restoration fencing/reconciliation, credential/rate-limit performance and independent adversarial verification. No production readiness or equivalent browser proof-of-possession protection is claimed.

## Stage 03 API qualification — 2026-11-28

Native Spring Security WebAuthn 7.2.0 and its managed WebAuthn4J 0.31.11.RELEASE dependency are declared/locally inspected. Public RP operation, credential/user repository, option/response builder and Jackson 3 WebauthnJacksonModule contracts were inspected with javap. Adapters scope each RP to an approved company hostname and allowed origin; public credential fields persist through application repository ports rather than unqualified built-in JDBC schemas. No package-private framework APIs or production visibility widening is used. The preserved configuration test remains in com.saaserp.erp.config.

TOTP declares `com.eatthepath:java-otp:1.0.0`. Its [versioned public source](https://github.com/jchambers/java-otp/tree/java-otp-1.0.0) and [public API](https://jchambers.github.io/java-otp/apidocs/latest/com/eatthepath/otp/TimeBasedOneTimePasswordGenerator.html) confirm SecretKey/Instant generation, 30-second defaults and locale-specific string formatting; this adapter explicitly requests Locale.ROOT. No library artifact was downloaded and it was not cached during inspection. Existing Bouncy Castle 1.86 supplies maintained Base32 encoding; JCA AES/GCM supplies authenticated encryption. No custom cryptographic primitive is introduced.

New source/test compilation and runtime behavior remain owner verification. Browser support for PublicKeyCredential JSON parsing/toJSON must be tested at the actual approved HTTPS origins; unsupported implementations fail rather than using a weaker policy. Hardware attestation, trusted metadata and independent privileged recovery remain unqualified and therefore blocked. External email delivery is not implemented. Follow the [Stage 03 handoff](phase04-stage03-mfa-account-protection.md); no new experimental project, dependency download, test execution or infrastructure change was performed by the agent.
